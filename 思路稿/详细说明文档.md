# 详细说明文档（模块与函数解析）

本文档详细拆解了“格律约束解码”代码库中各个模块的具体职责、内部方法逻辑以及模块之间的调用关系。当您后续遇到报错或需要进行代码修复与扩展时，请参考此文档。

---

## 模块与类的调用关系总览

```text
main.py (入口点)
 ├── DataManager (基础数据管理)
 ├── VocabIndexer (离线词表索引, 依赖 DataManager)
 ├── GenerationStateMachine (生成状态跟踪, 依赖 DataManager)
 └── ConstraintLogitsProcessor (概率截断, 依赖 VocabIndexer 和 GenerationStateMachine)
      └── 注册进入 transformers 的 LogitsProcessorList
```

---

## 1. `data_manager.py` (数据管理模块)
**职责**：负责从本地 JSON 文件中加载《词林正韵》字库信息和 `songci.json` 中的词牌格律配置。它是最底层的知识库。

- **`__init__(self, cilin_path, songci_path)`**：初始化路径，并立即调用加载方法。
- **`_load_cilin(self)`**：
  - 读取字典。
  - 构建 `rhyme_tone_to_chars` (给定韵部和平仄，查字)。
  - 构建核心映射 `char_to_rhyme_tone`：`字典[字] -> [(韵部, 平/仄), ...]`。这里使用了列表，以防多音字存在于不同韵部或平仄。
- **`_load_songci(self)`**：读取并存储整个词牌配置文件。
- **`get_cipai(self, name)`**：对外暴露，提取出特定词牌（如“浣溪沙”）的字典结构。
- **`get_pingze(self, char)`**：查询单字，返回它所有可能的平仄属性（如 `["平", "仄"]`）。
- **`get_rhyme_part(self, char)`**：查询单字，返回它所有可能的韵部。

## 2. `vocab_indexer.py` (词表预处理与索引构建)
**职责**：HuggingFace 的 Tokenizer 词表往往高达十多万。此模块仅在启动时运行一次，过滤出纯中文字符 Token，并记录它们的平仄组合序列，大幅缩短推理时的查询时间。

- **`__init__(self, tokenizer, data_manager)`**：保存引用并触发 `_build_index`。
- **`_is_pure_chinese(self, text)`**：正则表达式判定 Token 完全由汉字组成。
- **`_get_all_pingze_patterns(self, text)`**：
  - 核心递归/循环函数。如果一个 Token 是多字词（如“天下”），则拼接它们分别的平仄，组合成形如 `"平仄"` 的字符串。
  - 对于多音字构成的词，会返回多组组合（例如第一字两读，第二字一读，则返回两个长为2的组合）。不在字典里的字直接导致该词失效。
- **`_build_index(self)`**：
  - 遍历 `tokenizer.get_vocab()` 全局词表。
  - 清理特殊前缀（如 ` ` 或 `Ġ`）。
  - 对每个纯中文 Token：
    1. 计算长度和的所有平仄序列（如 `length=2, pz="平仄"`），注册进 `pattern_tokens[(长度, 平仄)]`。
    2. 针对它的**最后一个字**，记录它的押韵属性，存入 `rhyme_tokens[(平/仄, 韵部)]`。

## 3. `state_machine.py` (生成状态机)
**职责**：跟踪当前正在填词牌中的哪个位置。处理一韵到底和“中”字诀展开。

- **`__init__(self, cipai_name, data_manager)`**：设定所需词牌，展平 stanza（阕），重置诸多指针游标（如 `current_stanza`, `current_line`, `current_char_idx`）。
- **`get_current_line_info(self)`**：获取当前尚未写完的那句原始平仄字符串（带有“中仄平平...”）。
- **`_is_rhyme_position(self)`**：查询 JSON 的配置，判别当前句的末尾是否是押韵位。
- **`_expand_zhong(self, pattern)`**：将如 `"中仄"` 的字符串展开为 `["平仄", "仄仄"]`，覆盖全部可能性。
- **`get_allowed_patterns(self, max_length=4)`**：
  - **关键推断点**：根据目前还差几个字（`remains`），允许尝试长度 `L ∈ [1, min(max_length, remains)]`。
  - 获取字串切片，展开“中”字。
  - **押韵拦截**：如果当前探讨的正好是句末最后一个字，并且是押韵句：
    - 若已经锁定韵部 (`locked_rhyme_part`)，则只允许该韵部。
    - 若还未锁定韵部，标记为 `"ANY_RHYME"`。
  - 返回值为 `[(长度, 平仄模式串, 特殊韵部要求), ...]` 列表给外界。
- **`advance_state(self, text)`**：
  - 外界（模型）真实吐出文字后调用。
  - 推进游标。一旦遇到首个押韵位填完，立即捕获该字韵脚，锁定 `self.locked_rhyme_part`。
  - 自动跨越句子和上下片，直至 `is_finished = True`。

## 4. `logits_processor.py` (逻辑运算与掩码注入)
**职责**：嵌入 Transformers 中，拦截每一次预测概率，应用暴力掩码。

- **`__init__(self, vocab_indexer, state_machine, tokenizer, input_prompt_len)`**：记录 Prompt 初始长度。
- **`__call__(self, input_ids, scores)`**：
  - **同步状态**：每次调用截取 `input_ids` 中除了 prompt 以外的新生成张量。解码为 `new_text`，找出相比上一次多出来的 `latest_char`，喂给 `state_machine.advance_state()` 推进内部状态。
  - **结束处理**：如果 `is_finished`，利用 `-inf` 将全表拉平，仅保留 EOS (结束) token 概率，强迫模型停止。
  - **请求合法 Tokens ID 集合**：
    - 调用 `state_machine.get_allowed_patterns()`。
    - 遍历得到的每一个允许的 `(长度, 平仄, 韵部规则)`：
      - 从 `vocab_indexer.pattern_tokens` 拿出满足基础平仄的候选 ID 集合。
      - 如果有 `"ANY_RHYME"` 或具体的韵部需求，则利用集合求交集（`intersection`）跟 `vocab_indexer.rhyme_tokens` 结合，做二次过滤。
      - 合并（`update`）到总 `allowed_tokens` 中。
  - **施加掩码**：
    - `mask = torch.full_like(scores, -float('inf'))`
    - `mask[0, allowed_tensor] = scores[0, allowed_tensor]`
    - 最后当合法列表不为空时返回 mask；否则触发 EOS 兜底。

## 5. 跨模块协作流 (以 `main.py` 为例)

1. **资源装配**：实例化 `DataManager`，并传给 `VocabIndexer` 和 `GenerationStateMachine`。
2. **预充缓存**：`VocabIndexer(tokenizer, data_manager)` 执行完毕，获取数十万条 Token 属性记录。
3. **注入流水线**：利用 `LogitsProcessorList` 封装 `ConstraintLogitsProcessor` 实例。
4. **引擎滚动**：在 `model.generate(..., logits_processor=processors)` 的每一步前向传播中，底层会自动调用 `Processor.__call__`。
5. **动态追踪与遮罩**：`__call__` 先把上一步生成的词送进状态机，再从状态机拿到当前空缺位要求的平仄要求，去查 `VocabIndexer` 获取 ID 并在当前步的 softmax 以前对非法 ID 打上负无穷的分数标签。最终实现无暇格律输出。
